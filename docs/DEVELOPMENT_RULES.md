# DEVELOPMENT RULES


1. READ ONLY PHILOSOPHY

The Guardian NEVER modifies the customer's system.


--------------------------------------------------


2. ONE TARGET AT A TIME

Every target must be completed before moving to the next one.


--------------------------------------------------


3. SETTINGS DRIVEN ARCHITECTURE

No hardcoded values.


--------------------------------------------------


4. TARGET STRUCTURE

Every target must contain:

- Settings
- Manager
- Collector
- Tests
- Git Commit


--------------------------------------------------


5. DEVELOPMENT WORKFLOW

Write Code

↓

Run Tests

↓

Commit

↓

Push

↓

Next Target


--------------------------------------------------


6. NO RESTORE FUNCTIONALITY

The Guardian only creates technical snapshots and backups.


--------------------------------------------------


7. NO FEATURE CREEP

A feature is added ONLY if it helps:

- Technical Support
- Technical Snapshot
- Disaster Recovery
- Customer Migration


--------------------------------------------------


8. TARGETS FIRST

The Guardian Engine is implemented AFTER all targets are completed.
